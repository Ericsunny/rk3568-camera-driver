### [2026-10-09] AI · L2-lite 受阻 → rkaiq 根因考古 + ISP21 自建(进行中)

**现象**:板上 `rkaiq_3A_server` 裸跑(它不收 -i/-s 参数,usage 后仍继续执行)→ 一串 entity null 日志 → `CamHwIsp20.cpp:1075: No free isp&ispp needed by fake camera!` Exit 255。

**调查链(每步有证据)**:
1. **初判"内核缺 ISPP 驱动要移植"被推翻**:①SDK 全 dts 目录 grep rkispp 零命中;②defconfig `VIDEO_ROCKCHIP_ISPP not set`;③ispp 驱动 compatible 只认 rv1126;④**官方文档+网络确认:RK3568=ISP2.1,ISP/ISPP 一体,单 rkisp_vir0 即完整拓扑,无独立 rkispp 是正常现象**——板上 9 节点 rkisp-vir0 就是全部。内核侧无需任何移植。
2. **板上二进制取证**:`grep -ao 'CamHwIsp[0-9]*' librkaiq.so` 同时含 20/21 两族符号(胖构建,运行时选)。
3. **源码考古(vicharak-in/camera_engine_rkaiq 镜像,raw 单文件精准抓取)**:
   - `rkaiq_3A_server.cpp`:server 主流程 = 枚举 /dev/media* → 找 rkisp 四实体 → `rk_aiq_uapi2_sysctl_getBindedSnsEntNmByVd(mainpath)` 问库 sensor 绑定 → 无 sensor 则不 init;
   - `uAPI/rk_aiq_user_api_sysctl.cpp`:**版本选择 = 运行时按 s_info->isp_hw_ver(4=ISP2.0,5=ISP2.1)new CamHwIsp20/21**;
   - `CamHwIsp21 : virtual public CamHwIsp20` 继承——**initCamHwInfos 只在基类文件定义,所以日志出现 CamHwIsp20.cpp 文件名 ≠ 走了 20 路径**(关键去误判);
   - initCamHwInfos 支持 sensor 直挂 ISP 媒体设备的拓扑(`else if (isp_info)` 分支),RK3568 直连理论上被支持;
   - 板上 model="rkisp0" 正确命中 model_idx=0;日志里 entity null 全是 `if(entity)` 保护的可选查询,非死因;

- 深层嫌疑:①IQ 大量枚举解析失败(v4 日志 6+ 条 unknown enum:AECV2_STRATEGY_MODE_LOWLIGHT_PRIOR/RK_AIQ_SENSOR_HDR_LINE_MODE_STAGGER/CALIB_AWB_HDR_FRAME_CHOOSE_MODE_MANUAL 等)→ AE/AWB 的 stats 使能默认配置可能没被正确装入;②meas 配置下发链路还有未明差异;③内核侧 procfs(/proc/rkisp-vir0 空壳)/debugfs 无出口,内核动态调试未开
- **结论:至此进入"vendor 栈前向移植"的深水区**——继续修=完成整个用户态↔2019内核UAPI 的兼容层+IQ 格式迁移,多日工程;位图/枚举逐项验证的方法论已就绪(kb 09/11 可复用)
