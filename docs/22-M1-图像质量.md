# M1 图像质量：从"糊"到可用（P0 物理对焦 + 锐化真相）

> 日期：2026-10-22
> 设备：RK3568 + IMX415（4K，`rkisp` mainpath，NV12）
> 结论一句话：**糊的主因是镜头物理失焦，不是 ISP 参数**。手动对焦后同场景全帧锐度指标提升 **155%**；`A Sharp 未生效` 的旧判断是误判，实测开关锐化差 **458%**。

---

## 1. 现象

4K 采集的图看起来"整体发虚"，1:1 看中心裁切是一团雾，文字/线缆边缘不实。第一反应是"驱动/ISP 参数没调好"，但需要先把"光学问题"和"参数问题"分开。

## 2. 诊断：先排三个嫌疑

### 2.1 排除"假 4K"（驱动只给了半分辨率再上采样）

对同一帧做逐级下采样，看 Laplacian 方差是否单调下降：

| 下采样倍数 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| lap_var | 29.7 | 14.3 | 7.3 | 5.8 |

真正的 4K 细节在 2 倍以上下采样会显著损失；若是"半分辨率上采样"，下采样 2 倍后信息量几乎不变、lap 不会继续掉。**结果单调下降 → 是真 4K**，排除。

### 2.2 交叉验证：同平台另一颗 sensor 是清楚的

OV8858（`/dev/video0`，RAW10 compact）在同场景下的边缘明显更实。两颗 sensor 共用同一套 `rkisp`。**说明 ISP 管线本身没问题**，问题在 IMX415 这条链路上的光学部分。

### 2.3 定位：光学失焦

- 全帧 lap_var = **14.3**（清晰图像通常 > 300）
- 逐行找最强梯度做 10–90% 上升宽度：**边缘宽度中位数 28 px**（对 4K 来说等于全糊）

IMX415 模组是**手动对焦镜头**（螺纹旋转），出厂/运输后镜片位置会偏。到此可以确定：**P0 = 拧镜头对焦**，不是调参数。

## 3. 修复：量化对焦（P0）

### 3.1 工具

板上 `/root/focus_score`（源码 `tools/focus_score.c`）：

```
focus_score <dev> <frames> <out.nv12> [w h]
```

- 每帧 4×4 下采样后算 Sobel 梯度均值（`score`，主判据）+ 拉普拉斯响应（`lap`）
- 实时打印进度条与当前最优，把最优帧写成 `.nv12`
- 前 8 帧丢弃（AE 收敛中，亮度变化会污染分数）
- **必须**：收到 SIGINT/SIGTERM 时 `STREAMOFF` + `close` 再退出。直接 `kill -9` 一个正在流式采集的进程会把 `rkisp` 卡死（`rkisp_stream_stop id:0 timeout`），只能重启板子——这是本项目踩过的坑。

配套 `/root/focus_right.sh`：连续采样 90 秒并打印 `best=`，用于"拧一点、看一次"的迭代。

### 3.2 迭代与数据

同一场景（天花板），拧镜头后立刻复测：

| 阶段 | score | lap | 全帧 lap_var | 边缘宽度中位 | 有效边数 |
|---|---|---|---|---|---|
| 原始 | 17 630 | 36 | 14.3 | 28.0 px | 71 |
| 第一次旋转 | **30 530** | 241 | **36.5**（+155%） | **11.0 px** | 164 |
| 精扫（换场景后） | 41 826 → best **44 367** | 703 | 51.8 | — | 379 |

> ⚠️ 精扫那一轮相机已被挪到桌面/板子方向，**场景不同，分数不能和上一行直接比**。同一场景的干净对比是前两行：lap_var 14.3 → 36.5，边缘宽度 28 → 11 px。

### 3.3 对焦判据（可复现）

固定机位、固定目标，用 `score` 找极值：相邻两次旋转的 `score` 差 < 2% 即收敛。目标建议用打印的 A4 对焦图（`tools/make_focus_chart.py` 生成，300 dpi：西门子星 + 四个斜边方块 + 1–8 px 线宽阶梯），贴在实拍距离处；没有打印机就用任何有高频细节的固定物体（书页小字、包装条码）。

**收敛后必须锁死镜头**（点胶/锁紧螺丝），否则前功尽弃。

## 4. 纠错：`A Sharp 未生效` 是误判

之前看到日志里 `not support snr mode:127`，据此判断"锐化没生效"，并计划去改 sensor 的 snr mode。**这个判断是错的**，源码与实测都推翻了它。

### 4.1 `snr_mode:127` 是什么

`rkaiq/algos/asharp3/rk_aiq_asharp_algo_v3.cpp:318`：

```c
if (snr_mode == 1)      sprintf(snr_name, "%s", "HSNR");
else if (snr_mode == 0) sprintf(snr_name, "%s", "LSNR");
else { LOGE_ASHARP("... not support snr mode:%d!\n", snr_mode);
       sprintf(snr_name, "%s", "LSNR"); }   // 回退，正常返回
```

IMX415 走线性模式，没有声明 HDR/SNR 模式，AIQ 内部拿到 `127`（未定义），于是打印一行错误并**回退到 LSNR 标定表**，函数照常返回成功。**锐化没有因此被关闭**。

### 4.2 实证：同一 AE/AWB 下只切锐化开关

把 IQ 的 `sharp_v3.TuningPara.enable` 从 1 改成 0，其余不动，各跑一次 3A + 采一帧：

| 条件 | 全帧 lap_var | 平均 |lap| | focus_score |
|---|---|---|---|
| 3A + 锐化 **开** | **81.3** | 5.43 | 33 145 |
| 3A + 锐化 **关** | 14.6 | 2.30 | 30 079 |
| 不开 3A（ISP 默认参数） | 54.4 | 3.31 | 44 347 |

- 锐化开/关：lap_var **+458%**，1:1 目视边缘明显变实（`evidence/m1/sharp_off_on.png`）。
- 不开 3A 时也有 54.4，说明 `rkisp` 默认寄存器带着一定锐化；但不如 AIQ 下发的那套。
- `focus_score` 在"不开 3A"时反而更高（44k vs 33k）：因为不开 3A 时 AE 没收敛、整体更亮，梯度幅值随亮度升高。**跨曝光条件不能只比 score**，要比同条件。
- 结论：**A Sharp 一直在工作**。原计划的"改 snr mode"取消。

## 5. 还剩下的真实软点（诚实清单）

| 项 | 现状 | 归因 |
|---|---|---|
| 视场边缘偏软 | 中心实、四周略糊 | 树脂镜头的场曲/像散，非软件可解 |
| 高光溢出 | 窗户整片 255 | AE 目标亮度 + 无 DRC，属 M3 动态范围 |
| 暗部噪点 | 可见彩色噪点 | 增益较高，属 M2 噪声底 |
| 细节仍不及手机 | 4K 但像素小（1.45 μm） | 光学上限，靠锐化只能"看着实" |

## 6. 复现步骤

```bash
# 1. 固定机位、贴上对焦图
# 2. 拧一点，测一次
/root/focus_right.sh                 # 打印 best=，Ctrl-C 退出
# 3. 收敛后锁死镜头
# 4. 最终证据帧
/root/focus_score /dev/video5 20 /root/focus_final.nv12 3840 2160
```
