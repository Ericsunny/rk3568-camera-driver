# M4 工程化：让这台相机"开机就能用、坏了能自证"

> 日期：2026-10-22
> 目标：把前面几个里程碑的成果从"手工能跑通"变成"开机能用、换人能查"。
> 三件事：**3A 开机自启**、**版本闸门**、**一键自检**。

---

## 1. 为什么需要这一步

到 M3 为止，链路是通的，但每次验证都要人工记四条 md5、手动起 daemon、记得"必须先起 3A 再开流"。任何一个环节记错，现象都是"图不对"或"卡死"，而且**看起来和驱动 bug 一模一样**——本仓库前面踩的坑里，至少有一半是这个原因：

| 现象 | 真实原因 |
|---|---|
| `AWB` 崩、`invalid main scene len` | 2024 库 + 2022 IQ 混装 |
| `Can not get isp params buffer` ×114 | 同上，params 队列拿不到 buffer |
| 枚举 `-ENOTTY` | 驱动是内建 `=y`，装 `.ko` 根本不生效 |
| 出流但 AE 不动 | daemon 在流启动**之后**才起，错过 stream start 事件 |
| 两个 daemon | 手工起了一个 + systemd 又起一个，抢同一个 params 设备 |

所以工程化的核心不是"多写脚本"，而是**把这些隐性前提变成可检查的断言**。

## 2. 3A 开机自启

### 2.1 厂商原方案的问题

板子自带的 `/lib/systemd/system/rkaiq_3A.service`：

```ini
[Service]
Type=forking
ExecStart=/etc/init.d/rkaiq_3A.sh start
ExecStop=/etc/init.d/rkaiq_3A.sh stop
```

两个硬伤：

1. `Type=forking` 但**没有 `PIDFile=`**，systemd 只能靠猜来判定主进程，`systemctl stop` 未必停得干净。
2. init.d 脚本的 `stop_3A()` 用的是 `killall rkaiq_3A_server`，而板子上**没有 `killall`**：

```
/etc/init.d/rkaiq_3A.sh: line 20: killall: command not found
```

也就是说厂商这套**根本停不掉** daemon。再叠加 `rkaiq_3A` 默认 `disabled`，实际状态就是"从来没自启过"。

### 2.2 换成直接托管

不套 init.d，直接让 systemd 盯进程（`tools/install_3a_autostart.sh`）：

```ini
[Service]
Type=simple
ExecStart=/usr/bin/rkaiq_3A_server
Restart=on-failure
RestartSec=3
```

- `Type=simple` + 前台进程 → 主 PID 明确，`systemctl stop/restart` 可靠。
- `Restart=on-failure` → daemon 挂了自动拉起，不必人工介入（顺带缓解"杀掉 daemon 就卡死"的老问题，因为会立刻重起）。
- 原来的 init.d 脚本保留不动，回滚只需 `systemctl disable --now rkaiq_3A`。

### 2.3 启动顺序是硬约束

2022 库的 daemon 在初始化时会 `wait stream start event`。实测：

- **先起 daemon、后开流** → 正常，AE/AWB 接管；
- **流已经在跑、再起 daemon** → 日志停在 `wait stream start event...` 之后**再无一行**，AE 永远不动（不是崩溃，是错过事件后死等）。

开机自启天然满足"daemon 先于业务"，这正是它比自己手起更可靠的原因。

### 2.4 实测

冷启动后：

```
$ systemctl is-active rkaiq_3A
active
$ ps -ef | grep -c rkaiq_3A_server        # 只有 1 个
1
$ /root/grab /dev/video5 120 ...

  帧  90: Y   74.2  U  125.9( -2.1)  V  124.6( -3.4)
$ v4l2-ctl -d /dev/v4l-subdev6 --get-ctrl exposure,analogue_gain

```

AE 从 Y≈39 爬到 73 后稳定（当前室内光照下的收敛点，此前夜间场景收敛到 110），曝光值 275 与场景亮度一致 —— **自启链路成立**。

## 3. 版本闸门

`tools/install_rkaiq_2022.sh` 与 `tools/camera_selfcheck.sh` 都把"配套关系"写成 md5 断言：

| 文件 | 必须等于 |
|---|---|
| `/usr/lib/librkaiq.so` | `654dc84e89edc0aae9ee5f646732ba62` |
| `/usr/bin/rkaiq_3A_server` | `bc67a0fc6ca1221923132c65c3381aed` |
| `/etc/iqfiles/imx415_...json` | `0666ba18ce1e4db30cddc92810587fb1`（默认）/ `a72f52e6…`（高光优先开） |

第三条特别说明：IQ 的开关键 `OverExpCtrl.Enable` 只改一个字符，所以"高光优先"模式下 md5 会变，自检脚本因此不把 IQ 的 md5 写死，而是**校验 JSON 合法 + 打印当前 Enable 值**——闸门要卡的是"三件套是否配套"，不是"配置文件是否没被动过"。

## 4. 一键自检

`tools/camera_selfcheck.sh`（板上 `/root/`），6 组检查，退出码即结论：

| 组 | 检查 | 为什么查这个 |
|---|---|---|
| 1 | `/proc/kallsyms` 有 `ov8858_sm_enum_frame_size` | 内建驱动 `=y`，装 `.ko` 无效，只能靠符号判断"跑的是哪份代码" |
| 2 | media1 有 `m00_b_imx415`、media0 有 `ov8858-sm` | 实体名不合 Rockchip 约定 → 3A 认不出 sensor |
| 3 | `/dev/video5|12|13`、`/dev/v4l-subdev3|6`、`/dev/media0|1` | 节点缺失时现象是"设备忙"，极易误判 |
| 4 | 三件套 md5 + IQ JSON 合法 | 2024/2022 混装是本项目最大的坑 |
| 5 | daemon active、**恰好 1 个进程**、日志无 params buffer 报错 | 两个 daemon 会互抢设备；这条报错是 3A 失效的直接证据 |
| 6 | 实拍 60 帧：能出流、≥10 fps、Y 在 8~200 | 最终用户视角的"能不能用" |

实测输出：

```
===== 1. 内核驱动 =====
[ OK ] 补丁驱动已生效（ov8858_sm_enum_frame_size 在 kallsyms 里）
       kernel: 4.19.232 / build: #32 SMP Wed Oct 21 14:38:47 UTC 2026
===== 2. media 实体 =====
[ OK ] rkisp 侧实体名合规（m00_b_imx415）
[ OK ] rkcif 侧 OV8858 实体在（ov8858-sm，非 Rockchip 命名但 2022 库容忍）
...
[ OK ] 出流正常：  帧  30: Y   67.3  U  126.5( -1.5)  V  124.1( -3.9)
[ OK ] 帧率 14.0 fps（≥10）
[ OK ] 亮度 Y=67.3 落在合理区间（8~200）
=====
结论：全部通过 ✅
```

`-q` 只查配置不实拍（约 1 秒），适合开机自检或 CI。

## 5. 运维手册（这几条都是用板子换来的）

1. **改驱动必须重编内核刷 `/boot/Image-4.19.232`**。`CONFIG_VIDEO_OV8858_SM=y`，`make && insmod` 是无效动作，`modprobe` 只会回 `module is already loaded`。
2. **绝不 `rmmod` / `pkill`**。`rmmod ov8858_sm` 会让 rkcif 的 notifier 与 media 图死锁，整机挂死（本仓库真的挂过一次，靠断电恢复）；`pkill rkaiq` 会让 ISP 卡在 stream 未停状态（`rkisp_stream_stop id:0 timeout`），之后开 `/dev/video5` 拿不到帧，只能重启。要换 daemon 用 `systemctl restart`。
3. **脚本一律 LF**，但现在也不需要"去 CR"——踩过的坑：`sed -i "s/\r$//"` 在这块板子上把行尾的 `r` 当成了 `\r` 来替换，于是 `ExecStart=..._server` 被削成 `..._serve`，systemd 报 `status=203/EXEC`。**仓库里的脚本本来就是 LF，不要再做 CR 清洗。**
4. 自检失败优先看第 5 组（daemon）和第 4 组（md5），这两组出问题的概率远高于驱动本身。

## 6. 剩余缺口

| 缺口 | 影响 | 计划 |
|---|---|---|
| DRC 不可用（2022 库取不到 adrc 参数） | 逆光只能整幅压暗 | 见 `docs/23`，真解是 DOL-HDR |
| OV8858 实体名不合规 | 2022 库容忍、2024 库拒绝 | 改 `sd->name` 为 `m01_b_ov8858` 后重编 |
| 无 HDR / 3DNR 调优 | 动态范围与暗部噪声 | 下一阶段 |
| 双摄（L3）未纳入自检 | 自检只覆盖 rkisp 单路 | 扩成"双路自检" |
