# 31 - 程序与证据对照表(M6 产物)

> 目的:**任何一个性能数字,都能在这里定位到"哪个程序、哪个提交、什么输入输出、哪里在拷贝"。**
> 本表只做索引,不重复解释;细节看对应文档。
>
> 基线提交:`7f74780`;内核 `4.19.232 #42 SMP`;板卡 RK3568(iTOP-3568 clone)。

## 0. 为什么需要这张表

仓库里有三代东西混在一起:

1. **历史优化实验**(`zerocopy/`,2026-10-21):证明零拷贝/流水线/NPU 绑定的收益,**不是**当前服务;其 mode C 链路做到了**输入+输出全 native**(RGA 直写输入 tensor dmabuf + 输出 `rknn_create_mem`+`set_io_mem`),README 的"0 B/帧"指它;
2. **当前服务**(`tools/camd.c`):双消费者 + 有界队列;`--rknn` 默认拷贝路径;`--npu-native`(实验)做到**输入 native**(RGA 直写输入 dmabuf + `mem_sync(TO_DEVICE)`),**输出仍经 `rknn_outputs_get` 拷回**——"0 B"只对输入成立,`cpu_copy_bytes` 也只统计输入;
3. **专项一次性工具**(HDR 演示、稳定性压测、对焦打分等):各有各的输入输出。`evrec` 的检测路径当前仍为 `rknn_inputs_set` 拷贝路径,无 native。

一句话:**`zerocopy/` 输入+输出全 native;`camd --npu-native` 输入 native、输出拷贝;`evrec` 全拷贝路径。**

不分开写,就会出现"拿 41 ms 的推理耗时去描述一个走 `rknn_inputs_set` 的程序"这种错误。

## 1. 当前服务

| 程序 | 提交 | 输入 | 输出 | 拷贝点 | 证据 |
|---|---|---|---|---|---|
| `tools/camd.c`(CPU 拷贝消费者) | `c73c995` | `/dev/video0` BG10 1632×1224 mmap | 进口队列→RT/EV 两消费者 | EXPBUF 导 fd 后**仍 memcpy 整帧** | docs/29 §5.4 |
| `tools/camd.c --rga` | `c73c995` | 同上 | RGA 缩放到 640×360 | 无 CPU 拷贝(RGA 直读 dmabuf) | docs/29 §5.4 |
| `tools/camd.c --rknn` | `c73c995` | `/dev/video5` NV12(或 video0) | 检测框 + JSON 指标 | **RGA 缩放到本地 RGB 缓冲 → `rknn_inputs_set` 拷进 NPU**;输出走 `rknn_outputs_get` | docs/29 §5.10 |

**关键更正:** `camd --rknn` **不是**零拷贝。它做过一次 native IO 尝试,但输出绑定 native 张量时 SIGBUS,最终退回"RGA 写本地 RGB + `rknn_inputs_set`"。**任何引用 41 ms 推理耗时的地方,如果指的是 `zerocopy/zc_npu.cpp`,不能与 camd 混用。**

## 5. 使用规则

1. 引用性能数字 **必须** 同时给:程序名 + 提交 + 分辨率/格式 + 测试时长;
2. 跨程序不比较绝对值,只比较**同一程序**内的相对变化;
3. 旧实验的结论只能写成"当时在该程序上测得",不能外推成当前能力;
4. 新增程序 → 先在这张表里加一行,再写文档。
