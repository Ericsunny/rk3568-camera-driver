## 1. 内核问题闭环（M5）

### 1.1 `VIDIOC_TRY_FMT` 改变了实际模式

- **复现**：`./tryfmt_test`（`tools/tryfmt_test.c`）对 8 个格式/分辨率逐个 `TRY_FMT`，每次之后读 `G_FMT` 比对基线。
- **定位**：`ov8858_sm_set_fmt()` 在判断 `fmt->which` **之前**就执行了
  `ov8858->is_1080p = (w == 1920 && h == 1080);` —— 任何一次 TRY 都把全局模式改掉。
- **修复**：
  1. 拆出 `ov8858_sm_fill_fmt_mode(bool is_1080p, struct v4l2_mbus_framefmt *)`（无副作用）；
  2. TRY 分支只写 try 缓冲后 `return 0`；
  3. ACTIVE 分支在 `streaming` 时 `return -EBUSY`；
  4. 最后才写 `is_1080p`。
- **证明**（同一脚本同一机位）：

| | TRY 后 ACTIVE | 落盘大小 |
|---|---|---|
| 修复前（#40） | `1920x1080` **CHANGED** `changed=1/8` | `2211840` = 2048×1080（错） |
| 修复后（#41/#42） | `1632x1224` OK `changed=0/8` | `2506752` = 2048×1224（对） |

（`2211840` 这一行是关键：不只是 `G_FMT` 变了，**实际采集的帧也真的少了 144 行**。）

### 1.2 停流错误传不到用户态

- **复现**：`echo 5 > /sys/module/ov8858_sm/parameters/inject_stop_err` 后跑 `streamoff_test`。
- **定位**：`videobuf2-core.h:404` 的 `stop_streaming` 是 `void`，`videobuf2-core.c:1695` 用 `call_void_qop` ——
  **按 V4L2 规范 `VIDIOC_STREAMOFF` 恒返回 0**，驱动不可能让它返回 `-EIO`；
  rkcif 侧 `dev.c:577` 还把 `s_stream(0)` 的返回值直接丢弃。
- **修复**：驱动内部记录并暴露 `last_stop_err`、`stop_err_cnt`（`module_param(..., 0444)`），失败时 `dev_err`。
- **证明**：注入后 `last_stop_err=-5`、`stop_err_cnt=1`，dmesg 有
  `stop_stream failed: -5 (sensor 可能仍在出流)`，而 `STREAMOFF` 仍 `ret=0` —— 与规范一致，可定位。

### 1.3 两处补齐 + 一个内核 PAN oops

- `enum_frame_size`：设备端实现后，`VIDIOC_SUBDEV_ENUM_FRAME_SIZE` = **`0xC040564A`**
  （本内核 uapi 结构体带 `which` 字段，**sizeof = 64**，按 60 算会得到 `-ENOTTY`，极易误判成"没实现"）。
  实测：`index=0 → 1632x1224`、`index=1 → 1920x1080`、`index≥2 → EINVAL`。
- `compat_ioctl32`：64 位 OK，32 位**直接内核 oops**：
  `Unable to handle kernel access to user memory outside uaccess routines`，栈顶 `__memset ← ov8858_sm_compat_ioctl32`。
  根因是 `ov8858_sm_get_module_inf()` 对**用户指针**直接 `memset/strscpy`，绕过 uaccess。
  修法：本地结构体填好再 `copy_to_user`。修后 32/64 位均 `RESULT=OK`，oops 计数 0。

## 2. 可靠性工程（camd）

### 2.1 buffer 数与队列深度的硬边界

实测（`/dev/video0` 1632×1224，相机上限 30.3 fps）：

| `-b` | `rt_depth` | `ev_depth` | 和+2 | fps |
|---|---|---|---|---|
| 4 | 4 | 2 | 8 | **5.07** |
| 8 | 4 | 2 | 8 | 30.22 |
| 8 | 5 | 2 | 9 | **20.47** |

→ **`nbufs >= rt_depth + ev_depth + 2`**；等号成立正常，超出 1 就掉。
`+2` = 采集在途 1 + 每个消费者处理中 1。**buffer 不是排队长度，是在途资产。**

### 2.2 消费者策略

- `--ev-policy drop`（丢最旧）：**20.19 fps**，EV 处理 76 / 丢 224；
- `--ev-policy block`（有界阻塞）：**5.05 fps** —— 背压把采集压到取证速率。
→ 实时分支丢最旧、取证分支限速，两者不能共用一种策略。

### 2.3 RGA vs CPU 拷贝（100 帧，消费者耗时）

| 输入 | CPU 拷贝 | RGA 零拷贝 |
|---|---|---|
| 4K NV12 → 640×360 | 24.21 ms / 累计 2.645 s | **6.34 ms / 0.361 s** |
| BG10 1632×1224 → 408×306 | 19.32 ms / 2.053 s | **5.43 ms / 0.255 s** |

两臂 fps 相同（15.15 / 30.32）——**瓶颈在采集，零拷贝的收益在 CPU 与余量，不在帧率**。

### 2.4 回归

10/10 启停成功；1800 帧长跑 **30.04 fps**、首帧 58.9 ms、零泄漏；一次性故障后恢复并跑满 60 帧；
持续故障 rc=2 + 诊断包。

## 3. 检测（M7）

- **能力验证**：YOLO 官方 `bus.jpg` → `det=4`（person 0.76/0.75/0.73 + bus 0.71），证明模型/解码/NMS 正确。
- **实拍**：teddy bear `cls=77 score=0.57`。

| 条件 | 结果 |
|---|---|
| 人完整、顺光、1~3 m | 12/12，0.71~0.82 |
| 3 m | 8/8，最低 0.35（临界） |
| 遮挡约一半 | **0/12** |
| 只露头 | **0/13** |
| 近距离逆光 | **0/10** |
| 无目标 | 目标类 0/12；`chair` 稳定误检 |

**产品约束**：`cls==0` 且 `score ≥ 0.45` 且**连续 ≥3 帧**；安装须保证目标完整、顺光、1~3 m。
遮挡超过约 30% 即完全不可检出——这不是"检测率下降"，是能力边界。

## 5. 事件录像（M9）

```
>>> 触发 seq=260 ts=25400.9ms -> pre_i=220 pre_seq=220 (ring_cnt=260 head=0 pushed=260)
>>> 事件 1 完成, 继续等待下一个事件
>>> 触发 seq=301 ts=29397.3ms -> pre_i=15 pre_seq=286 (ring_cnt=30 head=0 pushed=30)
>>> 事件 2 完成, 继续等待下一个事件
```

三个真 bug（详见 `docs/32-事件录像.md` §5）：
`MPP_ENC_GET_HEADER` 宏名错、**`rknn_query` 前没设 `attr.index`**（9 次查询全拿 0 号张量 →
`score_max` 恒 `0.000`）、`pre_i` 存环形下标（随 `head` 前移失效）。

判据：`mpp_dec_probe` 解出帧数 = 编码帧数 − 1（用已知 30 帧的对照实验校准）。

## 6. 复跑顺序（照这个顺序不会互相踩）

1. `systemctl disable rkaiq_3A && reboot` —— 释放 `/dev/video5`；
2. `./tryfmt_test` → 期望 `RESULT=PASS changed=0/8`；
3. `./streamoff_err.sh before` → 期望 `last_stop_err` 生效、`STREAMOFF ret=0`；
4. `./st_burn -c 300`、`./st_burn -t 180` → 期望 0 失败、0 丢帧；
5. `./camd -d /dev/video0 ... --rga` / `--cpu-copy` → 对比消费者耗时；
6. `./evrec ... --detect --det-score 0.45 --det-frames 3` → 人进画面应自动落盘；
7. `systemctl enable rkaiq_3A && start` —— 恢复出厂形态。

## 7. 已知边界（不做也不吹）

| 项 | 说明 |
