# 37 · 事件治理设计:evrec 从 ring-dump 走向流式事件写入

> 状态:**已批准,按 A(全量流式版)S1→S5 实施**。对应 issue #4(持续目标 2h 产生 834 个事件文件)。
> V1(止血抑制)不立项为最终方案,仅作为运营层参数(cooldown 60s 等)在需要时配置;
> 四处边界修正已并入(事件周期对账/体积对账/ring 与 seq 去重/writer 背压)。

## 1. 现状:为什么不能"改几个变量"

当前 `evrec.c` 的事件模型是 **ring-based 一次性 dump**:

```text
trigger → 等 post_sec → 从 ring dump pre+post → ring_clear → 等下一次 trigger
```

三个硬限制(见 `evrec.c:2740-2820`):

1. 事件结束即 `ring_clear()` —— 环只有 `--ring-mb 64`,装不下一个 300 s 的 4K 事件;
2. `dump()` 一次性把 pre+post 写成文件 —— 事件进行中没有任何数据落盘;
3. `g_streak` 是"连续命中帧数",检测**偶尔漏一帧就归零** —— 用它判断"目标是否持续在场"会把长事件拆碎。

所以"持续目标合并为一个事件"**不是状态机加变量,而是写入架构的变化**。

## 2. 产品语义(先回答两个问题)

| 问题 | 决定 |
|---|---|
| 持续目标要一条长事件,还是允许分段? | **允许分段,但必须有意为之**:达到 `--max-event-sec` 时在 IDR 边界切段,`event_id` 不变、`segment_index++`。段与段之间无缝(都在实时写,不存在 ring 装不下的丢失)。 |
| 事件期间实时写,还是继续 ring dump? | **实时写(流式)**。pre-roll 部分仍从 ring 取(从最近 IDR 起),trigger 之后的每个编码包直接 append 到当前事件文件。 |

## 3. 目标架构:流式事件写入(streaming event writer)

```text
                    ┌─ 无事件: 每 frame → ring(滚动)
编码器出包 ──┬──────┤
             │      └─ 事件中: append 到 event.h264(同时 ring 照滚,供下一个 pre)
             │
检测触发 ────┴─→ 无事件时: 开临时文件 → 从 ring 取 pre-roll(自最近 IDR)→
                  逐包 append; last_detect_ms 持续刷新
                  事件结束判定: now - last_detect_ms > post_sec
                  → close → rename → 写 JSON → (进 cooldown)
```

### 3.1 事件延长判定:用 `last_detect_ms`,不用 `streak`

- 每次检测命中刷新 `last_detect_ms`(单调时钟);
- `now - last_detect_ms > post_sec` 才算"目标离开";
- streak 只保留给**触发门限**(连击 N 帧才开始一个事件),不参与延长判定。
  这样检测单帧丢失不会把 10 分钟目标切成碎文件。

### 3.2 分段(segment)与冷却(cooldown)语义分离

| 情形 | 行为 | 事件计数 |
|---|---|---|
| 目标持续,达到 `--max-event-sec` | 在 **IDR 边界**切段:close 当前段,立刻开新段文件 | `event_id` 不变,`segment_index++`;**不进 cooldown** |
| 目标离开超过 post_sec | 事件关闭 → **进 cooldown** | `cooldown_until = now + cooldown_sec` |
| cooldown 内再次触发 | 记 `cooldown_skipped`,不开新文件(检测与采集照常) | 不计入事件 |
| cooldown 结束后再触发 | 新 `event_id` | 正常 |

JSON 字段(每段一份):`event_id`、`segment_index`、`close_reason`(`target_left` / `max_duration` / `disk_low` / `sigterm`)、
`coalesced`(本事件吞掉的后续触发数)、`cooldown_skipped`、`disk_free_mb`(关闭时刻)。

### 3.3 磁盘水位:两阈值 + 滞回

- **开新事件前**:`statvfs` 检查 `free < disk_min_mb` → 不开,检测计数照走,记 `disk_low`;
- **事件进行中**:每 10 s 查一次;低于水位 → **先收尾当前文件**(close+rename+JSON,`close_reason: disk_low`),之后不再开新事件;
- **滞回**:低于 `disk_min_mb` 进入"停录"态后,须回升到 `disk_min_mb + hysteresis`(默认 +1 GB)才允许开新事件——避免 500 MB 边界反复启停;
- 水位计算必须把**当前事件已写体积**算进去;体积按实测对账:
  117 个样本平均 **1.48 MB/事件**(短事件,pre+post 窗口);
  连续 300 s 事件按 `--kbps 4000`(4 Mbps ≈ 0.49 MB/s)≈ **146 MB**——与 soak 样本体积量级一致,
  故 `disk_min_mb` 默认 500 MB 可容纳 ~3 个满长 300 s 段,合理。

### 3.4 ring 语义与 seq 去重(writer 的两个暗坑)

- **事件结束路径移除 `ring_clear()`**:ring 必须照滚,否则下一个事件的 pre-roll 无从取起;
  复位集合收窄为 `g_trigger=0 / g_pre_seq=0 / trigger_i=pre_i=end_i=-1`(`g_streak` 归零保留——
  它只是触发门限的状态,不是事件状态);
- **pre-roll 与实时 append 按 `seq` 去重**:trigger 帧本身已在 ring 里,writer 打开文件后
  先写 ring 中 `seq < trigger_seq` 的部分,实时路径只 append `seq >= trigger_seq` 的新包,
  否则首帧重复;

### 3.5 writer 背压(必须有,否则磁盘慢会拖死采集主循环)

- 用户态 4 MB 写缓冲,攒批发写(`fwrite` 批量),**绝不逐包 fsync**;
- 写路径全部非阻塞语义:flush 超时(>200 ms)或写失败 → **立即收尾当前文件**
  (`close_reason: write_error`),进入与 `disk_low` 相同的停录态,检测与采集照常;
- 任何情况下 writer 不得阻塞采集/编码线程——"fps 不下降"优先于事件完整性;
- 缓冲满且 flush 失败:丢当前事件剩余数据(已在 ring 里的仍可事后人工分析),记 `write_error`。

### 3.6 各场景下的完整落盘

| 场景 | 保证 |
|---|---|
| SIGTERM / USR1 退出 | 当前事件 close+rename+JSON(`close_reason: sigterm`) |
| 链路故障恢复(link_recover) | 事件中断处继续(编码器不动),段内标注 gap;若编码器重建则按 `max_duration` 同款切段 |
| max-duration 切段 | 新段从 IDR 起(编码器 gop 边界自然满足;切段点即 IDR) |

## 4. V1 止血方案(可选,与流式方案独立)

若时间不允许做流式写入,先做**事件抑制**(不冒充事件合并,文档/面试表述必须区分):

- `--cooldown SEC`(默认 10):事件关闭后的冷却窗;
- `--max-events N`:已有;
- `--disk-min-mb`:事件**之间**检查,低水位停录。

止血版预期(按实测事件周期 8.6 s/个对账):cooldown 10s → 周期 ~18.6s → **约 390 个/2h(约减半,不是降一个量级)**;
cooldown 60s(运营参数)→ ~113 个/2h。**持续目标仍是一个目标多个文件**——这解释了为何 V1 只能算止血,
也是选 A 不选 B 的量化依据。

## 5. 验收矩阵(流式版)

持续目标 10 分钟(镜头前持续有人):

- [ ] 事件数 = 1,或按 `--max-event-sec 300` 分段 **≤3 段**;
- [ ] 段间 IDR 边界衔接,pre/post 无丢失(逐段 ffprobe 帧数连续);
- [ ] JSON 每段含 `event_id/segment_index/close_reason/coalesced/cooldown_skipped/disk_free_mb`;
- [ ] 目标离开 ≥ post_sec → 事件关闭;冷却窗内再触发 → `cooldown_skipped` 不新建;
- [ ] 磁盘低水位:当前文件完整收尾,后续不开新事件;回升越过滞回带才恢复;
- [ ] SIGTERM:当前事件完整落盘;
- [ ] 全程无 D 状态、无 fd 增长、采集 fps 不下降。

止血版验收:cooldown/max-events/disk-min 三参数生效,2h 持续目标场景事件数 ≤120 且磁盘占用有上限。
