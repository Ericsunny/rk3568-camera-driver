## 开始前检查

1. 只读确认内核版本、启动时间、`/dev/video5` 当前格式、`rkaiq_3A_server` 及其他采集进程、可用空间、板钟和现场画面；记录结果。设备占用、3A 状态异常或画面含人员及隐私时停止处理，不停现役服务。
2. 在新建临时目录放置上述三个源码文件，逐个核对本地和板端哈希；用板端头文件和库编译独立的 `evrec-demo`，留编译输出及可执行文件哈希，不覆盖 `/root/evrec`。编译选项参照 Makefile：`gcc -O2 -Wall -pthread -DHAVE_RGA -DHAVE_RKNN -I/usr/include/rga -I/root/npu/3rdparty/rknpu2/include -o evrec-demo evrec.c rtsp_hub.c -lrockchip_mpp -lrga -lrknnrt -lm`。缺依赖或编译失败则停止并记录，不改系统库。
3. 确认 4K NV12 可用，输出目录有足够空间，3A 保持现有状态；镜头固定对准经确认可公开的静态物体。开测前记录命令、各参数和输入目录，确认捕获的内容可用于公开演示。

## 短时录像及核验

在隔离目录使用一次文件触发：设备 `/dev/video5`，3840×2160，`--pre 1 --post 2 --ring-mb 64 --kbps 4000 --max-events 1 --recover 0`，不启用检测和 RTSP；先启动，再等待至少 8 秒预热后创建专用触发文件。外层设置 40 秒超时并保留退出状态、stdout/stderr；若超时、无帧、错误或现场异常则停止，不声称通过。

核对进程成功结束、事件 `.h264` 和 `.json` 同时存在且非空；检查 JSON 的触发、时间范围和帧数，使用 `ffprobe` 和 `ffmpeg -v error -i <file.h264> -f null -` 检查流与解码错误，并记录命令、输出、退出码和哈希。播放和内容检查由维护者确认；对无效录像保留结果，不用它作演示。没有 H.264 原始逐帧时间戳的情况下，不把简单换容器后的播放时长当真实事件时长。

## MP4 封装

在电脑上安装 FFmpeg 和 FFprobe 后，可运行：

```bash
python tools/h264_to_mp4.py input.h264 output.mp4 --fps 15
```

`--fps` 必填，以现场记录的合理恒定帧率近似值替换示例的 15；并非从裸码流恢复真实采集时间戳。工具只复制 H.264 码流、不重编码，拒绝覆盖文件，并比较封装前后 FFprobe 解码帧数。帧数不同或 FFmpeg 失败即报错，输出不可作为演示；帧数相同也不足以证明时序准确或全部画面完好。FFmpeg 7.1 可能警告输入包缺时间戳，后续版本的兼容性未验证；变帧率、B 帧或断流片段尤其不能假定正确。录像 JSON 保留原样供时间对照。

主机测试：合成固定帧率、无 B 帧输入可封装，解码前后均为 10 帧；另一合成 B 帧样本出现 10→8 帧，工具检出并返回失败。历史板端 H.264 样本以 7.3 fps **假设值**封装，前后各 61 帧，输出未上传；两组都不是本次板测。历史样本含可辨认人员，不复用作新公开演示。
