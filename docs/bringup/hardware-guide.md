# 相机硬件接入与驱动调试

本文整理 RK3568 双摄项目中检查硬件连接、设备树和 V4L2 链路的方法。设备节点、内核配置及传感器接线可能随镜像和板卡变化，操作前应先检查现场状态。

## 硬件和总线

项目的历史连接方式为：IMX415 接 J10，走 ISP；OV8858 接 J11，走 CIF。历史设备树和实测分别将两个接口映射到 I²C1 和 I²C5；引脚与电源资料见 [I²C 排障记录](i2c-debug.md) 和 [双摄采集记录](../pipeline/dual-camera.md)。连接其他模组或更换设备树时，应重新核对接口、供电、电平、复位及 MIPI lane。

I²C 设备不可见时，可从以下方向逐项排查：

1. 根据板卡丝印、接线和设备树确认物理接口及对应 I²C 控制器。
2. 核对传感器供电、复位、时钟和 I²C 地址；必要时结合原理图和测量结果判断。
3. 查看内核日志、设备树状态及驱动匹配，再检查设备是否完成 probe。扫描 I²C 总线前应确认设备和现场条件允许。

## OV8858 驱动结构

[ov8858_sm.c](../../driver/ov8858_sm/ov8858_sm.c) 实现 V4L2 subdev 所需的设备匹配、资源获取、寄存器访问、格式协商、控制项和开关流；模式寄存器表与厂商实现的差异见[驱动对照](driver-comparison.md)。

驱动匹配成功只说明 probe 路径开始执行；要确认整条链路可用，还要检查 sensor、CSI、CIF/ISP 的 media 图、格式和实际采集结果。输出帧的大小与解释方式取决于节点格式、stride 和 sizeimage，不宜只根据图像宽高猜测。

## 编译与运行边界

历史 BSP 将 sensor 驱动编入内核。构建模块、重编内核、部署镜像和板上验证是不同步骤；先核对当前内核配置和工具链，不应直接按通用模块流程假定 `insmod` 生效。[驱动 README](../../driver/ov8858_sm/README.md) 保存历史构建说明，[源码状态](../acceptance/source-status.md)记录近期验证范围。

查看 media 拓扑、设备状态和日志时，先确认当前运行程序与 3A 服务。修改设备树、替换内核、启停共享服务或重启前，应确认影响与恢复方式；启动异常的历史案例见[恢复记录](../runbook/boot-recovery.md)。
