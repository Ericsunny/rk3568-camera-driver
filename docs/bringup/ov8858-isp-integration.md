# OV8858 ISP 接入与问题定位

目标是让自写 OV8858 驱动取得可供业务使用的彩色图像，并复用既有的人体检测、事件录像和 RTSP。单个应用实例选择一台相机：IMX415 经 ISP virtual 0；OV8858 经 CIF、SDITF 接 ISP virtual 1，再输出 NV12。RAW10 采集保留为诊断入口。后续使用两个独立实例完成了有限双路并发测试，结果及边界见[双路联测](../../evidence/2026-11-11-dual-followup/event02-natural-close.md)。

## 接入与控制

传感器仍以 Bayer RAW10 输出；ISP 负责形成 NV12，`rkaiq` 负责相关图像控制。sensor 驱动提供模式、曝光、增益、消隐和格式等接口，应用根据媒体图定位对应采集节点。OV8858 的媒体拓扑跨 CIF 和 ISP 图，不能简单依赖固定 `/dev/video` 编号。[驱动](../../driver/ov8858_sm/ov8858_sm.c) · [设备树候选片段](../../driver/patches/rk3568-ov8858-isp-candidate.dtsi) · [媒体图查找](../../tools/resolve_camera.py)

曝光控制转换为传感器 1/16 行寄存器单位；增益按 real-gain 格式写入。VBLANK 与曝光上限随模式和 VTS 约束更新，模式表配置后重放缓存控制。#60 上在停止采流和 3A 隔离的条件下改变曝光、增益，寄存器读回与设置对应，RAW 抽样均值也有变化；两者同时变化，不能分别计算响应量。[控制读回](../../evidence/2026-11-10-camera-integration/ov8858-controls-60/readback.txt) · [RAW 抽样](../../evidence/2026-11-10-camera-integration/ov8858-controls-60/raw-samples.txt)

## 兼容问题与判断

1. #59 启动后 rkaiq 的帧间隔枚举报错。排查发现它以宽高为零枚举，驱动原先拒绝；修正枚举后，#60 不再出现同一报错。这个发现针对现场 BSP 调用，不等于所有上层实现都使用相同参数。[#59 日志](../../evidence/2026-11-10-camera-integration/rkaiq59.log)
2. #60 仍报告方向和线性 HDR 设置失败。核对模式表后，#61 如实固定 HFLIP=1、VFLIP=0，支持线性 `NO_HDR` 并拒绝未实现的其他设置；流中寄存器读回与固定方向一致。不能把拒绝其他值说成支持任意翻转或 HDR。
3. 实物模组不是板上参考 IQ 文件的原配模组。候选 IQ 保留参考文件，只调整方向字段以匹配当前模式，按不同文件名使用；这能用于接入验证，不能证明颜色、镜头或画质已标定。[生成工具](../../tools/create_ov8858_iq_candidate.py)
4. 交付进程遇到板端 `ffprobe` 输出中非 UTF-8 字节时，一次已录像事件被正确标为交付失败。修正诊断文本解码后重测成功；真实解码错误仍会失败。[失败与复测](../../evidence/2026-11-10-camera-integration/README.md)

## 运行与边界

候选 #61 上分别验证两种相机的手动事件和 RTSP 双客户端回环；OV8858 还进行了无人、入镜、离开的自动事件短测，保留日志与元数据，人员视频仅留板端。[验证与版本指纹](../../evidence/2026-11-10-camera-integration/README.md)

候选先以串口临时引导，随后 #61 设为默认并重测，后来修复 IMX415 可选寄存器表的 #62 设为默认，#61 留有启动分区恢复副本。[修复与重测](../../evidence/2026-11-10-imx415-drc-review/README.md) OV8858 参考 IQ 随后启用了 DRC；参数提交和固定场景单变量对照有响应，启动时相关日志仍存在，且不代表完成本模组标定。[DRC 验证](../image/drc-validation.md) 两路并发有有限短测，不能据此推断复杂光照下的检测效果或长期运行表现。检测和编码处于同一主循环，检测耗时会影响实际吞吐；MP4 根据时间跨度估算平均帧率，不能作为逐帧真实时间轴。
