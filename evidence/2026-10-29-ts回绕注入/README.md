# 2026-10-29 ts 回绕注入测试(2 分钟替代 13 小时等待)

## 动机与绑定

RTP ts 为 32 位 @90kHz,自然回绕需 ~13.2h——等一夜不如定向注入。新增
`--ts-offset N`(rtsp_hub.c g_ts_off + setter,evrec 接线,~12 行,默认 0=关),
把回绕推到流时间 240s 处。binary = /tmp/h3src/evrec_ts md5 **ccd5fd75**
(源码 rtsp_hub.c=57ddb8a3 / rtsp_hub.h=cd55f303 / evrec.c=9338d7e8,双端一致)。

- 注入参数:`--ts-offset $((0xFFFFFFFF-90000*240))` = 4273367295(回绕@240s)
- 负载:1080p kbps4000,双客户端(ffmpeg 300s + python 裸 socket 300s),
  ffmpeg 接入于流 ~36s、python 于 ~36.5s——**窗口 36s→336s 覆盖 240s 回绕点**

## 判据三条款(全过)

| # | 判据 | 结果 |
|---|---|---|
| 1 | 客户端不中断不报错 | ffmpeg 300s **exit 0,零 discontinuity/corrupt,连等值 DTS 噪音都是 0**;python 300s 存活收 73.2MB ✓ |
| 2 | ts 模 2^32 单调 | trace 114267 包:**2^32 回绕边界恰 1 处**(4294965835→4845),跨回绕 uint32 差 = 6306 ticks = **70.1ms ≈ 恰好一帧间隔**;前向异常大步 0;唯一 >200ms 回跳 = 第二客户端接入瞬间的双游标交错(仅 1 次,join 偏差非时序回归)✓ |
| 3 | RTP-Info 与首包一致 | `rtptime=4276648324` == trace 首包 ts(逐字节相等)✓ |

**结论:"跨 13 小时 ts 回绕"风险被注入法直接证伪**——服务端/客户端全链在
回绕点行为正确(整帧语义、seq 连续、无客户端可感知事件)。

## 测试过程教训(如实)

- 前两轮失败均为**回绕点落在客户端窗口外**:①offset=60s 时本地任务卡死
  (ssh 启动+客户端同命令会挂,客户端分两次调用即愈),13 分钟后接入已绕过;
  ②工具调用间隔 ~2min,60s 窗口追不上。终版把回绕推到 240s,双侧余量 >2min。
- trace 混双客户端流:步差分析必须区分"2^32 回绕"(贴顶→小值)与
  "双游标交错"(小回跳),否则第一次分析会误报。
