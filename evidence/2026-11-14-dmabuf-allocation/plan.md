# MPP 分配共享采集池的验证方案

2026-11-14。现役 #62 内核与 3A 保持不变。已知旧的 V4L2 导出缓冲在 CPU 叠字对照中出现差异；根因未确定。新候选让 MPP 分配缓冲并由 V4L2 以 DMABUF 导入，CPU 访问以同步 ioctl 包围，输入任务返回核对后才重新 QBUF。先确认分配器 fdinfo 和导入支持，再以同一帧的复制/共享两套编码器做对照。

- 独立目录 `/root/zc-allocation-20261114-9juwLl`，不覆盖现役二进制、内核、配置，不启停 3A；画面/视频只留板端私有目录。
- 探针先 IMX415 1920×1080/15、120 帧，成功后 OV8858 1280×960/30、120 帧；OSD 开启，源帧与时间字段一致。若差异出现，停止扩大业务验证，保留码流并做离线定位；不能靠整帧 memcmp 或额外等待掩盖问题。
- 每帧核对 MPP 返回任务/输入帧/buffer/PTS，完成后才 QBUF；输出需完整解码、帧数正确、逐帧哈希一致，退出 0，3A 正常，无残留进程。探针双编码 CPU 时间不能当产品加速收益。
- 实时 /dev/kmsg 监测：CRC、CSI ERR1/2、超时、Oops、未知严重级别日志、监测丢记录、任一线程持续 D 状态 3 秒、程序总超时 90 秒立即停止。只放行已由源码和历史记录解释的精确 CSI-2 stream on/off 提示；出现未列出异常不再继续采流。
- 测试后在确认采集结束、无节点占用后恢复开测前 G_FMT，核对 3A、进程与内核状态。scp 核对 SHA-256。只在隔离验证成立后决定是否准备应用候选及完整服务测试，不能据探针通过直接替换默认版本。
