# OV8858 驱动补充评估：中止记录与当前结论

2026-11-14 15:41，板端 Linux 4.19.232 #62。测试目标和停止条件见 [plan.md](plan.md)。此前两驱动的基础同板对照见[前一轮记录](../2026-11-14-ov8858-driver-ab/README.md)。本轮只执行了自写驱动侧，发现 CSI-2 CRC 日志后停止，不切换厂商驱动继续采流。因此本轮不是完整的两驱动开关流对照。

## 本轮实测

- **枚举接口**：[实际 ioctl 输入和返回](self/enumeration.log)。`code=0x3007、width=height=0、index=0/1` 返回 1632×1224、1920×1080；给定 1632×1224 时 index 0 成功、index 1 返回 EINVAL。`code=0` 时本驱动也会返回模式：这是该实现的宽容行为，不单独证明任何驱动不符合标准，也未捕获 3A 调用时的实际 ioctl 参数。
- **TRY 与 ACTIVE**：[8 个试探格式后 ACTIVE 不变](self/tryfmt.log)。只覆盖该设备、该模式和此次输入，不意味着厂商驱动会失败。
- **3A 重启观察**：视频采集节点空闲时重启 3A，服务恢复 active；监视目录在重启时间窗内记录到 `ov8858_DC-21AF-58-1474V1_unknown.json` 被打开。[观察记录](self/iq_restart.log)。inotify 不提供打开者 PID，也不能证明文件已成功解析和生效；本轮没有得到厂商侧同样观察，不能据此认定两组实际 IQ 完全一致。
- **开关流异常**：测试程序 10 次均取得 6 帧并返回成功，但[内核增量](self/dmesg_delta.log)有 **4 条** `rockchip-mipi-csi2: ERR1: crc errors`，分别靠近第 5、6、7、10 次 sensor 开流。`cnt:1` 是日志内容，不能直接解释成恰好 4 帧损坏。原因和画面影响未知；不能将 10 次记为无异常通过。每轮日志见 [self/](self/)。

同类 CRC 文本在[历史双路记录](../2026-11-11-dual-followup/dual-event-userready-20261111/dmesg-delta.txt)也出现过；这只说明历史有过相同日志，不证明其无害或原因相同。核对 VM 厂商内核源码 `drivers/media/platform/rockchip/cif/mipi-csi2.c` 时，该文本由 CSI host CRC 错误位触发；这不等于确定是 sensor 驱动、线缆、电源或硬件的哪一处问题，VM 源码与本次镜像的精确对应仍需另证。

### 本轮执行失误

计划规定出现内核异常即停，但执行脚本只在 10 轮完成后读取 dmesg，没有在每轮之间或采集期间监控新增日志。因此第 5 轮出现第一条 CRC 后，脚本仍执行到了第 10 轮；这是测试执行不符合预注册停止条件，不能把它描述为已即时止损。发现后已停止进一步采流，也没有开始厂商侧本轮测试。后续若重新排查，应先补可验证的实时日志监控、隔离链路和回退步骤，再决定测试。

目前板卡仍使用默认 `ov8858-sm`，3A 运行、ISP 采集节点空闲；读取的 `last_stop_err=0`、`stop_err_cnt=0` 不能排除 CRC 或其他采集异常。

## 关于驱动优劣，目前能说明什么

| 方面 | 当前证据 | 不能推出 |
|---|---|---|
| 项目特定模式 | 自写驱动提供历史 1080p 裁窗；当前厂商 BSP 表中没有该 sensor 模式 | 当前业务必须用原生 1080p；厂商驱动整体不足 |
| 当前基础业务 | 前一轮两驱动均完成 1632×1224 采集、RTSP 软件解码和手动事件 | 两者画质、检测效果或长期可靠性相同 |
| 3A 枚举兼容 | 厂商侧启动日志有帧间隔枚举错误；自写侧重启日志未见相同文本，自写侧零尺寸枚举能返回模式 | 已确认该错误的确切 ioctl 参数或其全部影响；已证明厂商侧在相同探针下一定失败 |
| I²C 错误信息 | 当前自写源码对负错误码原样返回、短传输转 EIO；VM 厂商源码将非完整传输转 EIO | 板端已对两驱动做过同样故障注入；整机因此更可靠。VM 厂商源码未与 #62 内建对象建立完整源码指纹对应 |
| 停流诊断 | 自写驱动提供 `last_stop_err` 与 `stop_err_cnt`；历史实验有注入记录 | 本轮已复测停流错误注入，或 STREAMOFF 能直接向用户返回 sensor 停流错误 |
| 范围与缺陷 | 厂商源码支持更多 sensor 版本/模式；自写版本在本项目有定制适配 | 自写全面优于厂商。自写侧本轮也出现 CRC，源码中还存在模式注释和设备朝向口径待核对 |

对当前项目可成立的说法是：**选择自写驱动，是为了进行 sensor 接入和 BSP 适配实践；它提供了项目特定模式与诊断能力，前一轮可跑通基础业务。** 不应说“比厂商驱动全面更稳定/画质更好”。帧间隔错误需捕获双方同一请求的运行结果，CRC 需先调查；本轮补充 A/B 尚未完成。
