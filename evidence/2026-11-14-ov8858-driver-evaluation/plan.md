# OV8858 驱动接口与回归补充对照

沿用同一 #62 Image、同一设备树基线和前次仅改 compatible/厂商模式选择的临时 DTB；启动与恢复方法、哈希和风险控制见[前次对照](../2026-11-14-ov8858-driver-ab/plan.md)。

1. 两侧使用同一探针对 `/dev/v4l-subdev2` 在无采流时分别枚举：已知 Bayer code 与零 code、零尺寸和 1632×1224、index 0/1/2；逐个保留输入、返回值、errno 与输出，按实际接口解释，不将非标准输入的兼容性差异称为标准缺陷。
2. 两侧运行同一 `tryfmt_test`，观察 TRY 是否污染 ACTIVE；随后读取 ACTIVE 格式和控制项。确认无采流后，仅将同一 sensor 模式重新设置为 1632×1224，记录设置前后控制范围；它验证同模式设置，不测试 1080p 性能。
3. 两侧在 ISP NV12 1280×960、相同工具/参数、3A 运行下各做 10 次开关流，每次取首帧和 5 帧；单次失败、超时、内核异常或 D 状态即停。使用本目录的探针显式检查 QBUF、STREAMOFF 和帧数，保留其能力边界：STREAMOFF 的成功不能证明 sensor stop 回调没有失败。记录每次退出码、首帧耗时、错误和内核日志，不由此推断长稳。
4. 若条件允许，在无任何应用采流且视频节点空闲时，监视 `/etc/iqfiles` 文件打开事件并重启 3A，记录进程、日志与路径。inotify 不携带进程身份，观察到文件打开只能表明重启时间窗内发生访问，不能单独证明是 3A 成功加载；如能以更直接方式验证则另列证据。每次须恢复 3A 正常运行后才采流。
5. 任一引导失败即走原默认启动并停止；原 Image、DTB 与配置不覆盖。测试完成后恢复默认自写驱动、检查节点/3A。原始图像与录像不离开板卡；日志检查脱敏后入库。

本轮关注接口契约和短时表现。性能、画质、故障率、长期稳定及通用兼容性都需独立证据，不能预设自写驱动整体更好。
