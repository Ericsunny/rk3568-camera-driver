# evrec 文件故障注入夹具(主机已测,板测待排期)

这是事件录像故障注入测试辅助,不修改 `evrec`。用 `LD_PRELOAD` 仅给**显式启动的单个进程**模拟文件错误;**不得注入现役服务**,不得把它当安全沙箱。需先在独立、私有、无人并发写入的持久测试目录验证,板上使用需事先确认并隔离设备、输出和二进制。

## 已覆盖和未覆盖

| `EVFI_MODE` | 命中对象与动作 | 模拟的返回 |
|---|---|---|
| `json-open` | 匹配的 `.json` 写模式 `fopen`/`fopen64` | 不调用真实打开,返回 NULL、EACCES |
| `json-write` | 匹配流上的 `fprintf`/glibc `__fprintf_chk` | 尝试真实写入一个 `{`,随后返回 -1、ENOSPC;这是应用可观察的部分元数据及格式化写入失败,不是内核设备真实短写 |
| `json-close` | 匹配流上的 `fclose` | **先真实关闭**,再报告 EOF、EIO;模拟关闭报告失败,不代表真实文件系统关盘错误 |
| `video-write` | 匹配 `.part` 流上的 `fwrite` | 请求真实写入 `n-1` 个元素并报告其返回值、ENOSPC;用于模拟短写 |
| `video-rename` | 匹配 `.part` → `.h264` 的 `rename` | 不调用真实 rename,返回 -1、EIO |

每进程只触发一次;`EVFI_HIT` 选择**本模式下、匹配范围内**的第几次目标调用,从 1 开始。`json-write` 在 `fprintf` 层返回负数,对应现行代码对 `fprintf < 0` 的检查,不模拟其他未拦截的 libc 内部写路径。`video-write` 可能命中 pre-roll 或后续 flush,须用目标二进制和命中日志确认具体时机;不能把任意一次短写称为 SIGTERM 阶段注入。

不覆盖 `QBUF`/RGA、`fflush`、底层 `write`、`renameat`、其他输出 API、静态链接或绕过 interposition 的程序;缺少 `[evfi] HIT` 就是**未命中/无效**,不是通过。旧主机测试的 RGA-only 是提取片段测试,不代表完整 RGA-only 构建受支持。

拦截不是保证——fortified/内联写入可能绕过;A1 判据“未命中注入=无效”以命中日志为准。

## 安全边界和日志

必须设置全部四项:绝对目录 `EVFI_DIR`、文件名起始字符串 `EVFI_PREFIX`、`EVFI_MODE`、正整数 `EVFI_HIT`。夹具将目录解析为规范路径,只匹配该目录的**直接子文件**、指定前缀和相应后缀;现存符号链接或非普通文件不匹配。应用使用的路径必须以规范目录开头,相对路径或其他目录不会注入。日志写目标进程 stderr:`armed` 表示库已加载,`HIT` 记录模式、文件、进程和目标调用序号,`RESULT` 记录真实操作返回、向调用方报告的返回及模拟 errno;`real=-2` 表示故意没有调用真实操作。日志无法写出时进程以 125 退出,不能当验收结果。

夹具只决定是否**注入**,不阻止目标程序自己写其他路径;也不能防止其他进程在路径检查后竞态替换文件。使用新建私有目录、单独进程和独立输出前缀,先检查范围、权限、符号链接和 MD5,不要在含现役数据的目录测试。不要将 `LD_PRELOAD` 写入全局环境或 systemd 服务。

## 无设备验证

在具有 Python 3 和 C 编译器的 Linux 主机或 VM 的仓库根目录运行:

```sh
python3 tools/tests/test_evrec_preload.py
```

测试编译共享库,从当前 `evrec.c` 提取实际的 `ev_flush`、`evw_close`、SIGTERM 与 target_left 代码,在普通和 `_FORTIFY_SOURCE=2` 构建下检查正常对照与五种错误的退出码、完成计数、事件标识和文件结果;另检查目录/前缀/后缀、符号链接、未命中、指定第二次调用及配置失败。它是**主机提取代码测试**,不是完整 `evrec` 进程或真实设备测试。CI 运行同一测试。

## 板测窗口前准备

编译隔离副本的基本命令(在目标环境或匹配 sysroot 的交叉编译环境执行):

```sh
gcc -std=c11 -O2 -Wall -Wextra -Werror -shared -fPIC -pthread \
    tools/evrec_fault_preload.c -ldl -o libevfi.so
```

记录编译器、架构、libc、二进制哈希及链接符号;交叉编译成功不证明与板端 libc 兼容。准备执行时,用 `env` **仅为独立待测进程**传入 `LD_PRELOAD` 和上述四个 `EVFI_*` 参数,确保输出前缀/目录与 `EVFI_*` 一致,分别保存程序 stdout、stderr、退出码和文件状态。需同时有正常对照与确切 `HIT`/`RESULT`,逐项按 docs/41 核验事件状态。检查实际目标二进制导入符号和库加载输出;若符号不经由可拦截路径,标记 BLOCKED/未命中并另行设计测试构建,不得视作通过。

本轮只在 VM 的 x86-64 glibc 上运行了主机测试,并用 VM 工具链交叉编译 AArch64 共享库;[日志、源码哈希与工具链限制](../evidence/2026-11-05-无板夹具与编译/README.md)。**未在板端加载、未验证板端 libc 兼容性、未执行真实采集或故障注入**。完整事件状态及摄像头行为仍以窗口板测为准。
